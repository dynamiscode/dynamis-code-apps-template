## Current HTTP responses

These are handler responses before following redirects. Workspace routes also redirect unauthenticated sessions to login with 303; denied permission returns 403 and missing or inaccessible workspaces return 404. MFA may redirect to its challenge. Invalid CSRF returns 403; malformed management form data returns 400. Internal failures can return 500.

| Action | Success and failure responses |
|---|---|
| Files list, filter, sort, pagination | 200 page, including empty results; 400 invalid query or cursor; 500 list or preference failure. |
| Files column preferences | 303 to list after save/reset; 400 invalid value or preference error; 404 when unavailable. |
| File upload | 303 to list on success; 422 page for malformed multipart, missing, oversized, invalid or failed upload; 403 invalid CSRF or denied permission. A failure while rendering the page can produce 400 or 500 instead. |
| File download | 200 streamed local file; 302 redirect to S3 signed URL with `Cache-Control: private, no-store`; 404 missing/invalid file or failed local open; 500 other presigning failure. |
| Members list, filter, sort, pagination | 200 page, including empty results; 400 invalid query or cursor; 500 list or preference failure. |
| Members column preferences | 303 to list after save/reset; 400 invalid value; 403 forbidden preference operation; 404 when unavailable; 500 other preference failure. |
| Role change, removal, transfer | 303 to members on success; 422 rendered management error for invalid action, invalid role or rejected service operation; 500 if error page data cannot be loaded. |
| Invitations list | 200 page, including an empty list; 500 list or workspace lookup failure. |
| Invitation create and resend | 200 result page with link and optional delivery warning; 422 rendered management error for validation or service rejection; 500 result lookup or rendering prerequisites failure. |
| Invitation revoke | 303 to invitations on success; 422 rendered management error for rejection; 500 if error page data cannot be loaded. |
| Invitation entry | GET 200 for available invitation; 404 for unavailable invitation; 500 if CSRF token generation fails. |
| Invitation accept or register | POST 303 to workspace items on success; 400 malformed form; 403 invalid CSRF; 422 rendered invitation error on rejection; 500 if session creation fails. Authenticated acceptance without a session redirects to login. |

## Cross-cutting decisions

- **Swaps and statuses:** defer new swaps. Existing `app.js` configures no swap for 204, 304, 4xx and 5xx. Any future targeted response must explicitly handle validation and failures without silently losing input; preserve server status and focus an accessible alert. Do not assume error responses swap.
- **History and secrets:** retain native GET history for filters and pagination. The current invitation page puts the secret-bearing invitation path in `/login?return_to=`, so a secret is present in a query string today. #421 must replace this with a server-side, short-lived return mechanism that keeps the secret out of the login URL while preserving account matching and no-JS sign-in, and test browser history, logs and referrer handling. This is planned remediation, not current protection. Never snapshot invitation secrets, copyable URLs, signed download URLs or passwords; recheck cache headers and browser history before enhancements, and keep secrets out of logs and client draft storage.
- **Synchronization and loading:** native navigation remains the baseline. If list requests are added, coordinate competing requests and prevent stale results; if mutations are enhanced, block duplicate submissions without treating cancellation as server rollback. Show accessible pending, success and error feedback, preserve input and provide retry after uncertain outcomes.
- **Inheritance, DELETE and timeouts:** do not introduce inherited mutation attributes. Keep explicit POST forms and CSRF; no `hx-delete` is needed. Defer request timeouts until recovery from an unknown mutation outcome is designed; an aborted request may already have committed.
- **SSE, morphing, preload and `hx-live`:** defer for all these routes. No demonstrated live-update or preload benefit outweighs stale permissions, secret exposure, extra requests or loss of dirty input. Morphing and `hx-live` require proven focus, selected-file and draft preservation; SSE requires an authorized event source and a conflict strategy. Reconsider only with a measured need and browser tests. No extension compatibility with 4.0.1 is assumed.
- **Accessibility and fallback:** migrations must test desktop/mobile, keyboard and focus, English/Spanish, light/dark/system themes, validation, permission denial, empty, pending, success and failure states. Ordinary links and forms remain usable without JS. Destructive confirmation must also work without JS. Automated accessibility checks do not prove full conformance.

HTMX is pinned at 4.0.1 in `docs/capabilities.md`. The upstream [4.0.1 release](https://github.com/bigskysoftware/htmx/releases/tag/v4.0.1) documents fixes to `hx-sync`, history and inheritance; verify future behavior against the pinned distribution and its versioned docs. Context7 lookup did not return a result. Extension documentation and compatibility remain unverified for this version.

## Verification on 2026-11-16

- `go test ./internal/web/...` passed (174 tests), including the focused file, member and invitation handler tests cited above. These exercise selected success, validation, permission and failure paths through HTTP handlers, not a complete browser journey.
- `make accessibility-smoke` passed on retry using headless Chrome 157.0.8103.78. Axe reported zero violations on Files, Members and Invitations in English and Spanish at desktop size. The Files check also verified the named upload progress element and no horizontal overflow at 320 CSS pixels. This does not verify all states or establish WCAG conformance. The first run failed at `scripts/accessibility.mjs:198` with `StaleElementReferenceError` on an Items step, before reaching Files or Spanish.
- `make ux-smoke` passed 42 checks, including restoring, announcing and discarding an invitation draft. This does not exercise invitation submission. `make test` passed (26 JavaScript tests and all Go packages); `make lint` and `go generate ./api` passed.
- `npm ci` succeeded, but warned that Node 26.10.0 is below the Selenium package's required 26.12.1. Browser results were obtained despite that unsupported version.
- **Unverified:** route-specific keyboard navigation, dark/system themes, mobile Members and Invitations, browser history, JavaScript-disabled journeys and confirmation, upload progress during a real transfer, acceptance and the full success/empty/pending/validation/error/permission matrix. The existing smoke scripts do not cover these combinations. #417, #418 and #421 must cover them during migration; this review is not evidence that those checks passed.
