## Common decision and evidence

**Defer HTMX for every form and list below**, including targeted mark-read: no measured benefit outweighs new response, focus, synchronization and security paths. Keep native links and POST forms, full-page responses and redirects. For each deferred action the HTMX target, trigger, swap, request sync, HTMX loading indicator and HTMX history change are **none**. Native submission is the no-JavaScript fallback and provides browser navigation and loading; it does not guarantee duplicate-submit prevention or an in-page pending indicator. A browser navigation changes focus normally; current error alerts have their existing semantics, not a verified universal focus guarantee. Do not add speculative fragments or retry mutations automatically. Passkeys require JavaScript/WebAuthn; TOTP and recovery forms remain available where offered.

The shared renderer sends `Cache-Control: no-store`; public shares additionally send private/no-store, no-referrer and noindex. `h.redirect` uses 303. Server session/CSRF checks and shared identity policy remain mandatory, including on any future fragment request. Existing `app.js` suppresses HTMX swaps on 204, 304, 4xx and 5xx; do not assume upstream defaults apply. See [handler.go](../internal/web/handler.go), [alpine-components.js](../internal/web/assets/alpine-components.js), and [template upgrade evidence at the reviewed commit](https://github.com/dynamiscode/dynamis-code-apps-template/blob/81c496187ec060f359a38e844859c23c5e265931/docs/capabilities.md#htmx-4-upgrade-evidence). A future approved enhancement must define safe target-specific 4xx/5xx behavior, preserve entered non-secret data and focus, prevent duplicate actions, test ordinary fallback and avoid secrets in drafts or history snapshots.

## HTMX 4 and extensions

The vendored version is `htmx.org@4.0.1`. [Versioned upstream 4.0.1 documentation](https://github.com/bigskysoftware/htmx/blob/v4.0.1/www/src/content/docs/whats-new-in-htmx-4.md) describes explicit inheritance, response swaps, and server-backed history; [4.0.1 documentation](https://github.com/bigskysoftware/htmx/blob/v4.0.1/www/src/content/docs.md) covers targets and synchronization. Upstream 4 swaps error responses by default, unlike this app's compatibility handler. Keep ordinary full-page status handling. Do not inherit attributes implicitly, push HTMX history, send DELETE inputs, set HTMX timeouts or introduce `hx-sync` for these deferred forms. Native POST avoids DELETE parameter ambiguity; timeouts do not prove a mutation failed, so retries must not be automatic.

Defer preload and history-cache extensions for secret-bearing pages; defer morphing and `hx-live` because preserving credentials, dirty input and focus has not been demonstrated. Defer SSE extension because the stream sends JSON and has explicit cursor/resync semantics; native `EventSource` now reconnects with recipient-scoped replay. Extension versions and HTMX 4.0.1 compatibility are unverified; no extension is adopted here. [Upstream 4.0.1 release](https://github.com/bigskysoftware/htmx/releases/tag/v4.0.1) records relevant sync, history, SSE and hx-live fixes. Context7 indexed 4.0.0, not 4.0.1; tagged upstream documentation is the version authority.
